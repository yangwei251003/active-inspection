# 控制链路协议 v1（含兼容扩展 10–13、103）

115200 8N1，ASCII，严格 LF 行尾：`@seq,type,a,b*CCCC\n`。CRC16-CCITT-FALSE，poly `0x1021`、init `0xFFFF`、不反射、xorout 0；计算范围是 `seq` 到 `b` 的原始 ASCII，不含 `@`、`*` 或行尾。`123456789` 的校验为 `29B1`。不接受空白、CRLF、加号、指数、缺字段或多余字段。完整帧须短于内部 64 字节上限；遇到新 `@` 可以重新同步。CRC 错误与语法错误静默丢弃，让发送端超时，不对不可信帧作执行 ACK。

| type | 方向 | a | b |
|---|---|---|---|
| 1 | →STM32 | pan，300..1500 | tilt，450..1200 |
| 2 | →STM32 | preset index，0..active_count-1 | 必须0；超出当前有效点数拒绝 |
| 3 | →STM32 | 0 manual / 1 patrol / 2 paused | 必须0 |
| 4 | →STM32 | 必须0 | 必须0；有效心跳更新租约 |
| 10/11/12 | →STM32 | preset0/1/2 的 pan | 对应 tilt；巡检中拒绝，成功后暂停并作废旧稳定状态 |
| 13 | →STM32 | active_count，有效点数 1..3 | 必须0；巡检中拒绝，成功后暂停且 active_preset=255 |
| 101 | ←STM32 | 原命令 type | 接受/错误码 |
| 102 | ←STM32 | 当前**指令**pan | 当前**指令**tilt |
| 103 | ←STM32 | phase：0 idle / 1 moving / 2 settling / 3 dwelling | preset index 0..2 或255（无预置点） |

ACK 的 seq 与收到的命令相同。102/103 每约 200 ms 发送，seq 是最近已消费的命令编号 `last_seq`，**包括业务拒绝，不包括 CRC/格式错误和重复/旧序号**；**上行遥测的 seq 不是新的命令序号**。两个状态帧之间的采样有很小时间差，不是原子物理测量。移动 ACK=0 仅表示接受目标，不是动作完成；phase=3 也只表示逻辑时序已完成稳定等待。

错误：0 接受、1 参数范围、2 重复/旧序号、3 未支持类型、4 无有效心跳、5 板级输出禁用、6 巡检忙。除重放帧外，CRC/语法正确的输入即使业务拒绝也消耗 seq，防止其日后重发时突然生效。需要重试必须分配新 seq；丢失 ACK 时先查询/观察状态，不能将重放拒绝解释为之前必定未执行。

发送端为心跳、配置、运动、模式共享一个 16 位递增计数器。允许 65535→0。`delta=(new-last) mod 65536`，仅接受 1..32767；相同、反向或正好半空间的差值被拒绝。不能让心跳和控制各自独立计数。接收器首次有效帧接受任意 seq；这不是跨复位的密码学防重放协议。

**重启同步：** STM32 的 seq 只存在 RAM。协处理器单独重启后先清空自身过往命令队列和串口接收缓冲，等待完整 CRC 正确的 102/103 状态，再从 `(last_seq+1) mod 65536` 开始发送；先恢复心跳及 paused 状态，不恢复旧运动。STM32 尚未消费任何命令时遥测 seq 为0，此时发送1合法。不能依赖“等失联后任意 seq 都有效”。同一 UART 只允许一个发送者；初始化和心跳/业务命令要串行分配seq，避免恢复期间竞态。串口物理链路按同机可信连接处理，认证和公网命令过期在协处理器/服务端完成。生产硬件可另行加入 boot/session nonce 协议版本，不能声称 v1 已具备密码学防重放能力。

**过期限制：** v1 串口帧没有发送时间/有效期字段，因此 STM32 无法知道某条递增 seq 命令在互联网上滞留了多久。协处理器必须先检查 `expires_at` 和会话有效性，再发串口。STM32 独立执行 1500 ms 心跳租约；失联后清除未完成运动，不在重连后恢复旧目标。

建议命令顺序：心跳 → paused 并确认 ACK → 仅对有效点发送 10/11/12 且逐条核验 ACK → **13 提交有效点数并确认 ACK** → 才向服务报告该 revision 已 applied → 等待用户新操作 → preset 或 patrol。只配置两个点时必须发送 type13 的 a=2，不能保留第三个旧点继续轮转。不得把“更新点位”自动转化为恢复运动。

为兼容旧版，上电内置点数仍为3；配套协处理器必须在每次启动/重新同步后完成上述配置流程，才能开放 preset/patrol。`active_count` 范围始终为1..3；type2 范围检查及巡检轮转使用它，槽位容量仍为3。type10..12 可预写尚未启用的槽，type13 决定哪一段连续槽位可执行。更新失败不宣布 applied；不把逐条写入说成跨掉电原子事务。所有配置帧与心跳共用原16位seq防重机制，配置也不能启用默认被禁用的PWM。

显式 paused、失联、禁止板级输出、UART 错误/溢出均清除 active_preset 为255和未消费的 observation_ready。坐标或有效点数成功更新也如此。切换到 manual 空闲模式同样不保留旧观察点身份。因此 `103,0,255` 只表示无有效观察点的空闲状态，**idle 不能解释成已到达目标**。

取视觉 ROI 需同时确认 active_preset 与预期点相同、phase=3，再按视觉策略处理不确定性；physical position 仍未测量。完成 ACK 的判断应等待本条命令之后的新鲜 102/103，不能复用上条命令的 idle/dwelling 状态。

新增黄金帧：`@4,13,2,0*6A63\n` 提交两点；`@4,101,13,0*F13A\n` 接受计数；`@5,103,0,255*D9ED\n` 无活动点的空闲遥测。它们列在 `tests/protocol_vectors.json` 并在 C 主机测试中固定核验。
